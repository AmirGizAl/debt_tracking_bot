## 1. Назначение

Бот ведёт учёт денежных долгов между заказчиком (далее «владелец») и частными лицами (далее «клиенты»), а также учёт кассы владельца в пяти валютах.

Бот умеет:
- записывать четыре вида операций: «Выдал в долг», «Мне вернули», «Взял в долг», «Я вернул»;
- принимать возврат долга в другой валюте по курсу, который вводит пользователь;
- хранить по каждому клиенту один итоговый баланс в каждой валюте;
- вести кассу по каждой валюте, не допуская отрицательных остатков;
- отменять ошибочные записи (сторно) без удаления и изменения записей;
- работать с несколькими пользователями: владелец и помощники;
- формировать пять отчётов в Excel и PDF.

| Валюта оплаты | Валюта, в которой реально двигаются деньги в кассе. |

## 4. Валюты, суммы и курсы

### 4.1. Валюты

Поддерживаются пять валют:

| Код | Название |
|---|---|
| KGS | киргизский сом |
| USD | доллар США |
| EUR | евро |
| RUB | российский рубль |
| KZT | казахстанский тенге |

Этот порядок используется везде: на кнопках, в кассе и в отчётах.
Валюты задаются перечислением (`enum`) в коде. Отдельный справочник в базе не нужен.

### 4.2. Ввод сумм

- Допустимые форматы: `1000`, `1 000`, `1000,5`, `1000.50`, `1 000,50`. Пробелы, в том числе неразрывные, удаляются, запятая заменяется на точку.
- Сумма должна быть больше 0 и не больше `999 999 999 999,99`.
- После запятой допускается не больше двух знаков. Если знаков больше, это ошибка ввода, а не округление.
- При ошибке бот пишет, как правильно ввести сумму, и ждёт повторного ввода на том же шаге.

### 4.3. Ввод курса

- Формат такой же, как у суммы, но после запятой допускается до 6 знаков.
- Курс должен быть больше 0.

### 4.4. Вывод чисел

- Тысячи отделяются пробелом (в Telegram неразрывным), дробная часть отделяется запятой.
- Нулевые копейки не показываются: `1 000 USD`, `1 000,50 USD`.
- Код валюты пишется после суммы.
- Курс выводится без хвостовых нулей: `87,5`, `0,17`, `90`.

### 4.5. Направление курса (котировка)

Курс всегда вводится и хранится как «1 единица базовой валюты = X единиц котируемой валюты». Базовая валюта пары выбирается так:

1. Если в паре есть KGS, базовая валюта — вторая, котируемая — KGS. Бот спрашивает «Сколько сомов за 1 USD?», «Сколько сомов за 1 тенге?» и так далее.
2. Если KGS в паре нет, базовой становится валюта, которая стоит раньше в ряду `EUR, USD, RUB, KZT`.

Полная таблица пар:

| Пара | Вопрос бота |
|---|---|
| USD / KGS | Сколько сомов за 1 USD? |
| EUR / KGS | Сколько сомов за 1 EUR? |
| RUB / KGS | Сколько сомов за 1 RUB? |
| KZT / KGS | Сколько сомов за 1 KZT? |
| EUR / USD | Сколько USD за 1 EUR? |
| EUR / RUB | Сколько RUB за 1 EUR? |
| EUR / KZT | Сколько KZT за 1 EUR? |
| USD / RUB | Сколько RUB за 1 USD? |
| USD / KZT | Сколько KZT за 1 USD? |
| RUB / KZT | Сколько KZT за 1 RUB? |

### 4.6. Пересчёт оплаты в валюту долга

Даны сумма оплаты `pay_amount` в валюте оплаты и курс `rate` («1 base = rate quote»). Сумма, которая спишется с долга (`debt_amount`), считается так:
- если валюта оплаты базовая: `debt_amount = pay_amount × rate`;
- если валюта оплаты котируемая: `debt_amount = pay_amount ÷ rate`.

Результат округляется до 0,01 (`ROUND_HALF_UP`). Если после округления получился 0, это ошибка ввода: бот просит проверить сумму или курс.

Контрольные примеры (обязательно покрыть тестами):

| Долг в | Оплата | Курс | Спишется с долга |
|---|---|---|---|
| USD | 52 500 KGS | 1 USD = 87,5 KGS | 600 USD |
| RUB | 300 USD | 1 USD = 90 RUB | 27 000 RUB |
| USD | 1 000 KGS | 1 USD = 87,5 KGS | 11,43 USD |
| USD | 900 EUR | 1 EUR = 1,1 USD | 990 USD |
| KGS | 100 000 KZT | 1 KZT = 0,17 KGS | 17 000 KGS |

Вся логика курсов и пересчёта находится в модуле `app/domain/rates.py` в виде чистых функций без обращения к базе.

## 6. Модель данных

Все таблицы имеют `id BIGSERIAL PRIMARY KEY`. Все даты-время хранятся как `timestamptz`. Учётная дата операции хранится как `date` в часовом поясе из настройки `TZ`.

### 6.1. `users`

| Поле | Тип | Примечание |
|---|---|---|
| telegram_id | BIGINT NULL | Пустое, пока помощник не нажал /start |
| username | VARCHAR(32) NULL | В нижнем регистре, без `@` |
| full_name | VARCHAR(200) NULL | Имя из Telegram, обновляется при каждом /start |
| role | enum `owner`, `helper` | |
| status | enum `pending`, `active`, `deleted` | |
| added_by_id | FK users NULL | |
| created_at, activated_at, deleted_at | timestamptz | |

Индексы:
- уникальный частичный `telegram_id WHERE status <> 'deleted' AND telegram_id IS NOT NULL`;
- уникальный частичный `username WHERE status <> 'deleted'`.

### 6.2. `clients`

| Поле | Тип | Примечание |
|---|---|---|
| name | VARCHAR(100) NOT NULL | Обрезаны пробелы по краям, повторяющиеся пробелы схлопнуты |
| comment | TEXT NULL | До 1000 символов |
| created_by_id | FK users | |
| created_at, updated_at | timestamptz | |

Индекс: уникальный `lower(name)`.

### 6.3. `operations` — журнал операций, неизменяемый

| Поле | Тип | Примечание |
|---|---|---|
| request_id | UUID NOT NULL UNIQUE | Ключ идемпотентности, защищает от двойного нажатия «Сохранить» |
| type | enum `lend`, `repay_in`, `borrow`, `repay_out` | У отмены тип совпадает с типом исходной операции |
| client_id | FK clients ON DELETE RESTRICT | |
| debt_currency | enum валют | |
| debt_amount | NUMERIC(18,2) > 0 | Сколько изменилось в долге |
| cash_currency | enum валют | |
| cash_amount | NUMERIC(18,2) > 0 | Сколько денег прошло через кассу |
| rate | NUMERIC(18,6) NULL | |
| rate_base, rate_quote | enum валют NULL | |
| debt_delta | NUMERIC(18,2) | Изменение баланса клиента со знаком (см. 7.1) |
| cash_delta | NUMERIC(18,2) | Изменение кассы со знаком |
| op_date | DATE NOT NULL | Учётная дата |
| comment | TEXT NULL | До 500 символов |
| author_id | FK users NOT NULL | |
| created_at | timestamptz default now() | |
| reversal_of_id | FK operations NULL UNIQUE | Заполнено только у записи-отмены |
| reversal_reason | TEXT NULL | Обязательно, если заполнено `reversal_of_id` |

Ограничения `CHECK`:
- `debt_amount > 0 AND cash_amount > 0`;
- если `debt_currency = cash_currency`, то `debt_amount = cash_amount` и поля курса пустые; иначе поля курса заполнены и `{rate_base, rate_quote} = {debt_currency, cash_currency}`;
- для `type IN ('lend','borrow')` выполняется `debt_currency = cash_currency` (новый долг всегда в одной валюте);
- `reversal_of_id IS NULL OR reversal_reason IS NOT NULL`.

Триггер `BEFORE UPDATE OR DELETE` выбрасывает исключение `operations are immutable`.

### 6.4. `cash_adjustments` — корректировки кассы, неизменяемые

| Поле | Тип | Примечание |
|---|---|---|
| request_id | UUID NOT NULL UNIQUE | |
| currency | enum валют | |
| amount | NUMERIC(18,2), не равно 0 | Со знаком: плюс добавляет, минус убирает |
| reason | TEXT NOT NULL | До 500 символов |
| adj_date | DATE NOT NULL | Дата создания в часовом поясе `TZ` |
| author_id | FK users | Всегда владелец |
| created_at | timestamptz | |

Такой же триггер неизменяемости. Отменить корректировку нельзя: ошибка исправляется встречной корректировкой.

### 6.5. Что не хранится

Балансы клиентов и остатки кассы **не хранятся** отдельными полями. Они всегда считаются суммированием из `operations` и `cash_adjustments`. Если позже появятся проблемы с производительностью, добавлять материализацию можно только после согласования.

## 7. Правила учёта

### 7.1. Типы операций и их влияние

| Тип | Название в интерфейсе | debt_delta | cash_delta |
|---|---|---|---|
| lend | Выдал в долг | +debt_amount | −cash_amount |
| repay_in | Мне вернули | −debt_amount | +cash_amount |
| borrow | Взял в долг | −debt_amount | +cash_amount |
| repay_out | Я вернул | +debt_amount | −cash_amount |
| отмена любой операции | Отмена записи №N | −(delta исходной) | −(delta исходной) |

`debt_delta` применяется к `debt_currency`, `cash_delta` применяется к `cash_currency`.

### 7.2. Баланс клиента

```
balance(client, cur) = SUM(debt_delta) WHERE client_id = client AND debt_currency = cur
```

- Больше 0: «{Имя} должен вам: X CUR».
- Меньше 0: «{Имя}: вы должны X CUR».
- Равно 0: «{Имя}: долга в CUR нет».

Встречные долги в одной валюте сворачиваются автоматически, потому что это просто сумма. Балансы в разных валютах никогда не складываются и не пересчитываются.

### 7.3. Касса

```
cash(cur) = SUM(operations.cash_delta WHERE cash_currency = cur)
          + SUM(cash_adjustments.amount WHERE currency = cur)
```

### 7.4. Касса не может быть отрицательной

- Правило действует для любого действия, которое уменьшает кассу: `lend`, `repay_out`, отмена `repay_in` или `borrow`, корректировка в минус.
- Проверяется текущий остаток на момент сохранения, а не остаток на учётную дату. Если операция внесена задним числом, остаток на прошлую дату может оказаться отрицательным, и это допустимо.
- Проверка и вставка выполняются в одной транзакции. Перед проверкой берётся блокировка `pg_advisory_xact_lock` по ключу валюты кассы. Так два пользователя одновременно не смогут потратить одни и те же деньги.
- Если денег не хватает, сервис выбрасывает `InsufficientCash(currency, available, required)`, и бот показывает:
  ```
  Недостаточно денег в кассе.
  В кассе: 9 400 USD
  Нужно: 12 000 USD
  Запись не сохранена.
  ```
- Для удобства бот проверяет остаток уже на шаге ввода суммы. Если денег не хватает, он сразу сообщает об этом и просит ввести другую сумму. Окончательная проверка всё равно выполняется при сохранении.

### 7.5. Предупреждения при возврате

Предупреждения не запрещают операцию. Они выводятся на экране подтверждения жирным текстом перед кнопкой «Сохранить». Пусть `B` — текущий баланс клиента в валюте долга, `A` — сумма, которая спишется с долга.

| Условие | Текст |
|---|---|
| repay_in и B ≤ 0 | Внимание: клиент ничего не должен вам в {CUR}. Вся сумма станет вашим долгом перед ним. |
| repay_in и 0 < B < A | Внимание: сумма больше долга. Лишние {A−B} {CUR} станут вашим долгом перед клиентом. |
| repay_out и B ≥ 0 | Внимание: вы ничего не должны клиенту в {CUR}. Вся сумма станет долгом клиента перед вами. |
| repay_out и 0 < −B < A | Внимание: сумма больше вашего долга. Лишние {A−(−B)} {CUR} станут долгом клиента перед вами. |

### 7.6. Учётная дата

- Варианты выбора: «Сегодня» (по умолчанию), «Вчера», «Другая дата». Другая дата вводится в формате `ДД.ММ.ГГГГ` или `ДД.ММ` (тогда год текущий).
- Будущие даты запрещены.
- «Сегодня» определяется по часовому поясу `TZ` (по умолчанию `Asia/Bishkek`).

### 7.7. Идемпотентность

При входе в сценарий создания операции, отмены или корректировки в данные FSM записывается `request_id = uuid4()`. Повторное нажатие «Сохранить» с тем же `request_id` не создаёт вторую запись: сервис возвращает уже созданную.

## 8. Отмена записей (сторно)

1. Кнопка «Отменить запись» есть в карточке операции. Показывается она только если:
   - текущий пользователь является автором операции;
   - операция сама не является отменой;
   - операция ещё не отменена.
2. Пользователь вводит причину отмены (обязательно, 1–500 символов).
3. Бот показывает экран подтверждения:
   ```
   Отменить запись №15?
   Мне вернули: Тимур
   Сумма: 1 000 USD
   Причина: ошибка в сумме, должно быть 100

   После отмены:
   Тимур должен вам: 1 000 USD
   В кассе USD: 8 400
   ```
   Кнопки: «Да, отменить» и «Назад».
4. Сервис создаёт новую запись. Все поля в ней скопированы из исходной, кроме `request_id`, `author_id` (текущий пользователь), `op_date` (сегодня), `comment` (пусто), `debt_delta` и `cash_delta` (с обратным знаком), `reversal_of_id` и `reversal_reason`.
5. Правило неотрицательной кассы действует и здесь.
6. Сервис проверяет все условия повторно (автор, не отмена, не отменена). Уникальный индекс `reversal_of_id` гарантирует на уровне базы, что запись нельзя отменить дважды.
7. Результат: «Запись №15 отменена.» и новый баланс клиента.
8. Если отменил помощник, владельцу приходит уведомление (раздел 12.10).
9. Операции удалённого помощника отменить нельзя никому. Это осознанное правило.

Статусы в интерфейсе и отчётах:
- исходная операция: «отменена записью №M»;
- запись-отмена: «отмена записи №N».

## 9. Пользователи

### 9.1. Владелец

При каждом запуске бот создаёт или обновляет пользователя с `telegram_id = OWNER_TELEGRAM_ID`, ролью `owner` и статусом `active`.

### 9.2. Добавление помощника

1. Владелец вводит никнейм. Ведущий `@` и пробелы отбрасываются, никнейм приводится к нижнему регистру и проверяется по шаблону `^[a-z0-9_]{5,32}$`.
2. Если среди неудалённых пользователей такой никнейм уже есть, бот сообщает: «Этот никнейм уже добавлен».
3. Если есть удалённый пользователь с таким никнеймом, бот возвращает ему статус `pending` и очищает `telegram_id`. Иначе создаётся новая запись со статусом `pending`.
4. Ответ бота: «Помощник @aigul_k добавлен. Попросите его открыть бота и нажать «Старт».»

### 9.3. Активация

- На любой апдейт от пользователя, которого нет среди активных, бот проверяет: есть ли у пользователя `username` и совпадает ли он без учёта регистра с пользователем в статусе `pending`.
- Если совпадает, бот записывает `telegram_id` и `full_name`, ставит статус `active` и `activated_at`, показывает главное меню и отправляет владельцу уведомление.
- После активации пользователь определяется только по `telegram_id`, поэтому смена никнейма не ломает доступ.

### 9.4. Удаление помощника

- Удаление выполняется с подтверждением. Статус становится `deleted`, заполняется `deleted_at`, состояние FSM пользователя очищается.
- Доступ пропадает сразу, потому что проверка доступа выполняется на каждом апдейте.
- Операции удалённого помощника остаются. В интерфейсе и отчётах автор показывается как «Имя (удалён)».
- Удалить можно и помощника в статусе `pending`.
- Владельца удалить нельзя.

### 9.5. Проверка доступа

Проверку выполняет outer-middleware на `Message` и `CallbackQuery`:
- активный пользователь или владелец: апдейт обрабатывается, объект `User` передаётся в хендлер;
- иначе пробуется активация (9.3);
- иначе бот отвечает: «У вас нет доступа к этому боту.» Если у пользователя нет никнейма, добавляется: «Если владелец добавил вас, установите имя пользователя в настройках Telegram и снова нажмите /start.»

## 10. Клиенты

- Поля: имя (1–100 символов) и комментарий (необязательный, до 1000 символов).
- Имя уникально без учёта регистра. Если такое имя уже есть, бот отвечает: «Клиент «Иван» уже есть. Добавьте уточнение, например «Иван (Ош)» или «Иван Петров».» и ждёт нового ввода.
- Имя и комментарий можно изменить. Уникальность при изменении проверяется так же.
- Удалить можно только клиента без операций. Если операции есть, кнопка «Удалить» не показывается, а сервис всё равно проверяет это условие.
- Поиск идёт по подстроке без учёта регистра (`ILIKE '%...%'`).
- «Недавние» — до 6 клиентов с самой свежей операцией или, если операций нет, самые недавно созданные.

## 11. Общие правила интерфейса

- Все сценарии построены на inline-кнопках и FSM aiogram. Текст вводится только там, где без него не обойтись: сумма, курс, дата, имя, комментарий, причина, никнейм, поисковый запрос.
- На каждом шаге сценария есть кнопки «Назад» (на предыдущий шаг) и «В меню» (прервать сценарий и сбросить FSM).
- Команды: `/start` открывает главное меню (для неактивных пользователей запускает активацию), `/menu` открывает главное меню, `/cancel` прерывает текущее действие. Их нужно зарегистрировать через `set_my_commands`.
- Данные кнопок задаются через `CallbackData`-фабрики с короткими префиксами (ограничение Telegram — 64 байта).
- Если нажата кнопка устаревшего сообщения или сценария, бот отвечает всплывающим «Это действие устарело» и ничего не меняет.
- Длинные списки выводятся постранично, по 10 элементов, с кнопками «‹» и «›».
- Внутри сценария сообщения редактируются (`edit_text`). Итог сохранения отправляется новым сообщением, после него показывается главное меню.
- Сообщения форматируются через HTML parse mode. Пользовательские данные (имена, комментарии) экранируются.

## 12. Экраны и сценарии

### 12.1. Главное меню

Текст: «Выберите действие:». Кнопки в две колонки:

```
[Выдал в долг] [Мне вернули]
[Взял в долг]  [Я вернул]
[Клиенты]      [Касса]
[Отчёты]       [Настройки]   ← «Настройки» только у владельца
```

### 12.2. Выбор клиента (общий шаг для четырёх операций)

- Заголовок зависит от операции: «Кому выдаёте в долг?», «Кто вернул долг?», «У кого берёте в долг?», «Кому возвращаете долг?».
- Кнопки: недавние клиенты, «Найти», «Новый клиент», «В меню».
- Если пользователь просто напишет текст на этом шаге, текст считается поисковым запросом.
- «Новый клиент»: бот спрашивает имя, затем комментарий (можно пропустить), создаёт клиента и продолжает сценарий уже с ним.

### 12.3. «Выдал в долг» и «Взял в долг»

1. Выбор клиента.
2. Выбор валюты: пять кнопок.
3. Ввод суммы. Для «Выдал в долг» сразу выполняется предварительная проверка кассы.
4. Выбор даты.
5. Комментарий или кнопка «Пропустить».
6. Экран подтверждения:
   ```
   Проверьте запись
   Выдал в долг: Азамат
   Сумма: 1 000 USD
   Дата: 25.09.2026
   Комментарий: на ремонт машины

   После сохранения:
   Азамат должен вам: 1 000 USD
   В кассе USD: 9 000
   ```
   Кнопки: «Сохранить» и «Не сохранять». «Не сохранять» прерывает сценарий без записи.
7. После сохранения: «Запись №N сохранена.» и кнопка «Открыть запись» (из карточки можно сразу отменить свою запись).

### 12.4. «Мне вернули» и «Я вернул»

1. Выбор клиента.
2. Бот показывает текущие балансы клиента (только ненулевые, или «Долгов нет») и спрашивает «Какой долг закрывается?». Пять кнопок валют. На кнопке с ненулевым балансом виден баланс, например `USD · должен 600` или `RUB · вы должны 30 000`.
3. Кнопки «В этой же валюте» и «В другой валюте».
4. Если выбрано «В этой же валюте»: ввод суммы, для «Я вернул» с предварительной проверкой кассы.
5. Если выбрано «В другой валюте»:
   1. выбор валюты оплаты — четыре кнопки, кроме валюты долга;
   2. ввод суммы оплаты, для «Я вернул» с предварительной проверкой кассы в валюте оплаты;
   3. ввод курса с вопросом по таблице 4.5;
   4. бот считает сумму списания с долга (4.6).
6. Дата, затем комментарий.
7. Экран подтверждения с предупреждениями из 7.5, если они есть.

   Пример для оплаты в той же валюте:
   ```
   Проверьте запись
   Мне вернули: Азамат
   Сумма: 400 USD
   Дата: 10.09.2026

   После сохранения:
   Азамат должен вам: 600 USD
   В кассе USD: 9 400
   ```
   Пример для оплаты в другой валюте:
   ```
   Проверьте запись
   Мне вернули: Азамат
   Получено: 52 500 KGS
   Курс: 1 USD = 87,5 KGS
   Закрывает долг: 600 USD
   Дата: 27.09.2026

   После сохранения:
   Азамат: долга в USD нет
   В кассе KGS: 352 500
   ```
   Для «Я вернул» вместо «Получено» и «Закрывает долг» пишется «Отдано» и «Закрывает ваш долг».

### 12.5. Карточка операции

```
Запись №15 · Мне вернули
Клиент: Тимур
Сумма: 1 000 USD            (при другой валюте: Получено / Курс / Закрывает долг)
Дата: 25.09.2026
Комментарий: …
Автор: Айгуль · внесено 25.09.2026 14:03
Статус: отменена записью №17 (причина: …)   ← если отменена
```
Кнопки: «Отменить запись» (по условиям раздела 8), «Клиент», «В меню».

Для записи-отмены заголовок «Запись №17 · Отмена записи №15», добавляется строка «Причина: …», кнопки отмены нет.

### 12.6. Клиенты

- Экран «Клиенты»: список по алфавиту (постранично), «Найти», «Добавить», «В меню».
- Карточка клиента:
  ```
  Иван
  Комментарий: сосед, г. Бишкек

  Долги:
  USD: должен вам 700
  RUB: вы должны 20 000
  ```
  Валюты с нулевым балансом не показываются. Если все балансы нулевые: «Долгов нет».
  Кнопки: «История записей», «Выписка за период», «Изменить», «Удалить» (только если нет операций), «В меню».
- «История записей»: операции клиента от новых к старым, постранично. Строка кнопки: `№15 · 25.09 · Мне вернули · 1 000 USD`, у отменённых добавляется `· отменена`. Нажатие открывает карточку операции.
- «Изменить»: выбор «Имя» или «Комментарий», ввод нового значения, сохранение.
- «Удалить»: подтверждение, затем удаление.

### 12.7. Касса

- Экран «Касса»: остатки по всем пяти валютам, включая нулевые:
  ```
  Касса
  KGS: 352 500
  USD: 9 400
  EUR: 2 000
  RUB: 530 000
  KZT: 1 000 000
  ```
  Кнопки: «Движение денег», «Корректировка» (только владелец), «В меню».
- «Движение денег»: общий список операций и корректировок от новых к старым, постранично. Строка: `№15 · 25.09 · Мне вернули · Тимур · +1 000 USD` или `Корр. · 27.09 · −500 USD · Личные расходы`. Нажатие на операцию открывает её карточку. Это и есть «общий список записей» из описания для заказчика.
- «Корректировка» (только владелец):
  1. выбор валюты;
  2. «Добавить» или «Убрать»;
  3. ввод суммы;
  4. ввод причины (обязательно);
  5. подтверждение с новым остатком;
  6. сохранение.

  Для «Убрать» действует правило неотрицательной кассы.

### 12.8. Отчёты

Экран «Какой отчёт нужен?» с кнопками: «Общая сводка», «Кто кому должен», «Все записи за период», «Движение кассы», «Выписка по клиенту».

- **Общая сводка:**
  1. бот по очереди спрашивает курс для каждой валюты, кроме KGS, в которой остаток кассы не равен 0, в порядке USD, EUR, RUB, KZT: «Укажите курсы для пересчёта кассы в сомы. Сколько сомов за 1 USD?» и так далее. Если таких валют нет, шаг пропускается;
  2. выбор формата: «Excel» или «PDF»;
  3. бот присылает файл.

  Курсы в базе не сохраняются и влияют только на этот отчёт.
- **Кто кому должен:** выбор формата, файл.
- **Все записи за период и Движение кассы:** выбор периода, затем формата, затем файл.
- **Выписка по клиенту:** выбор клиента (как в 12.2, но без создания нового), затем периода, затем формата, затем файл. Выписку можно открыть и из карточки клиента.
- Варианты периода: «Этот месяц», «Прошлый месяц», «С начала года», «Всё время», «Указать даты». В последнем случае вводятся две даты в формате `ДД.ММ.ГГГГ`, начало не позже конца.
- Пока файл формируется, бот показывает действие «отправляет документ» (`ChatAction.UPLOAD_DOCUMENT`).

### 12.9. Настройки (только владелец)

- «Помощники»: список с пометками «активен» или «ожидает входа» и кнопка «Добавить».
- Карточка помощника: имя, @никнейм, статус, дата добавления, кнопка «Удалить» с подтверждением: «Удалить помощника @aigul_k? Доступ пропадёт сразу, его записи сохранятся.»

### 12.10. Уведомления владельцу

- Активация помощника: «Новый помощник в боте: Айгуль (@aigul_k).»
- Отмена записи помощником:
  ```
  Помощник отменил запись
  Кто: Айгуль (@aigul_k)
  Запись №15: Мне вернули · Тимур · 1 000 USD
  Причина: ошибка в сумме, должно быть 100
  ```
  К уведомлению прикладывается кнопка «Открыть запись».
- О каждой обычной записи помощника владелец уведомления **не** получает.

## 13. Отчёты: содержимое файлов

Общие требования:
- Каждый отчёт формируется в двух форматах: Excel (`.xlsx`) и PDF.
- В шапке указаны название отчёта, период (если он есть), дата и время формирования (в `TZ`) и имя того, кто сформировал отчёт.
- Суммы указаны в своих валютах, итоги считаются по каждой валюте отдельно. Единственное исключение — пересчёт кассы в сомы в «Общей сводке».
- Excel: строка заголовков закреплена, включён автофильтр, у числовых ячеек формат `#,##0.00` (Excel сам покажет разделители по региональным настройкам), ширина колонок подобрана по содержимому.
- PDF: формат A4 (для «Все записи» и «Движение кассы» альбомная ориентация), шрифт DejaVu Sans, заголовки таблиц повторяются на каждой странице, внизу номера страниц.
- В отчётах со списком операций отменённые записи и записи-отмены выделены серым цветом (заливка в Excel, цвет текста в PDF).
- Имена файлов: `Общая_сводка_2026-09-27.xlsx`, `Кто_кому_должен_…`, `Все_записи_2026-09-01_2026-09-30.pdf`, `Движение_кассы_…`, `Выписка_Иван_…`.
- Генерация отчёта — чистая функция: на вход подаются подготовленные данные (dataclass-ы), на выходе получаются `bytes`. Запросы к базе делаются отдельно, в сервисе отчётов.

### 13.1. Общая сводка (состояние на момент формирования)

**Таблица 1. Касса и долги по валютам.** Пять строк, по одной на каждую валюту.

| Валюта | В кассе | Вам должны | Вы должны | Разница |
|---|---|---|---|---|

- «Вам должны» — сумма положительных балансов клиентов в этой валюте.
- «Вы должны» — сумма модулей отрицательных балансов.
- «Разница» — «Вам должны» минус «Вы должны», со знаком.

**Таблица 2. Касса в пересчёте на сомы.** Строки только для валют с ненулевым остатком кассы. Для KGS курс равен 1.

| Валюта | Остаток в кассе | Курс, сомов за 1 | В сомах |
|---|---|---|---|

Последняя строка «Итого» содержит сумму колонки «В сомах». Каждое значение округляется до 0,01, затем значения складываются.

Долги в сомы **не пересчитываются**.

### 13.2. Кто кому должен (состояние на момент формирования)

- Раздел «Вам должны»: для каждой валюты, в которой есть положительные балансы, таблица «Клиент | Сумма», отсортированная по убыванию суммы, со строкой «Итого по валюте».
- Раздел «Вы должны»: то же для отрицательных балансов, суммы указаны по модулю.
- Один клиент может попасть в оба раздела.

### 13.3. Все записи за период

Отбор идёт по `op_date` в пределах периода, сортировка по `op_date`, затем по `id`.

Колонки:

| № | Дата | Операция | Клиент | Сумма долга | Оплата | Курс | Комментарий | Автор | Внесено | Статус |
|---|---|---|---|---|---|---|---|---|---|---|

- «Оплата» и «Курс» заполняются только при оплате в другой валюте.
- «Статус»: пусто, «отменена записью №M» или «отмена записи №N (причина)».

### 13.4. Движение кассы за период

По каждой валюте, в которой за период было движение или остаток не равен нулю:
- «Остаток на начало» — сумма всех движений с датой раньше начала периода;
- таблица движений за период: `Дата | № | Описание | Приход | Расход | Остаток`. Описание имеет вид «Выдал в долг — Азамат» или «Корректировка — Личные расходы». Корректировки не имеют номера `№`, вместо него пишется «корр.»;
- «Остаток на конец».

Сортировка: `дата`, затем `created_at`.

### 13.5. Выписка по клиенту за период

По каждой валюте, в которой у клиента есть хотя бы одна операция:
- «Остаток на начало» — баланс по операциям с `op_date` раньше начала периода, с формулировкой «должен вам» или «вы должны»;
- таблица: `Дата | № | Операция | Изменение долга | Оплата (если в другой валюте) | Баланс после`. «Изменение долга» показывается со знаком с точки зрения владельца: плюс означает, что клиент стал должен больше;
- «Остаток на конец» с формулировкой.

Принцип: хендлеры тонкие. Они собирают ввод, вызывают сервис и показывают результат. Любые проверки и расчёты находятся в `domain` и `services`, поэтому их можно тестировать без Telegram.

Сервисы выбрасывают доменные исключения (`InsufficientCash`, `PermissionDenied`, `AlreadyReversed`, `CannotReverseReversal`, `DuplicateClientName`, `ClientHasOperations` и так далее). Хендлеры переводят их в понятные тексты.

### 14.3. Запуск

- `docker-compose.yml` описывает три сервиса:
  - `db` — `postgres:16`, том для данных, healthcheck;
  - `redis` — `redis:7`, с включённым AOF;
  - `bot` — образ из `Dockerfile` на основе `python:3.12-slim`. При старте выполняется `alembic upgrade head`, затем `python -m app`. `restart: unless-stopped`.
- Логи пишутся в stdout. Каждое исключение в хендлерах логируется с трассировкой глобальным error-хендлером, а пользователь получает сообщение «Произошла ошибка. Попробуйте ещё раз или нажмите /menu.»
- `README.md` на русском описывает:
  - как создать бота у @BotFather и получить токен;
  - как узнать свой Telegram ID;
  - как заполнить `.env`;
  - как запустить, обновить и остановить бота;
  - как сделать резервную копию базы (`pg_dump`) и восстановить её.

### 15.1. Приёмочные сценарии

Сценарии 1–9 выполняются подряд на чистой базе.

1. Владелец вносит корректировки «Остаток на начало работы»: +300 000 KGS, +10 000 USD, +2 000 EUR, +500 000 RUB, +1 000 000 KZT.
2. «Выдал в долг» Азамату 1 000 USD. Ожидается: «Азамат должен вам: 1 000 USD», в кассе 9 000 USD.
3. «Мне вернули» от Азамата 400 USD. Ожидается: Азамат должен 600 USD, в кассе 9 400 USD.
4. «Взял в долг» у Бекзата 50 000 RUB. Ожидается: «Бекзат: вы должны 50 000 RUB», в кассе 550 000 RUB.
5. «Я вернул» Бекзату 20 000 RUB. Ожидается: вы должны 30 000 RUB, в кассе 530 000 RUB.
6. «Мне вернули» от Азамата: долг в USD, оплата 52 500 KGS по курсу 87,5. Ожидается: у Азамата долга в USD нет, в кассе 352 500 KGS, касса USD не изменилась.
7. «Я вернул» Бекзату: долг в RUB, оплата 300 USD, курс «Сколько RUB за 1 USD?» = 90. Ожидается: вы должны Бекзату 3 000 RUB, в кассе 9 100 USD.
8. «Выдал в долг» кому угодно 12 000 USD. Ожидается отказ «Недостаточно денег в кассе… В кассе: 9 100 USD. Нужно: 12 000 USD», ничего не записано.
9. «Общая сводка» с курсами USD 87,5, EUR 100, RUB 1,1, KZT 0,17:
   - таблица 1: KGS 352 500 / 0 / 0 / 0; USD 9 100 / 0 / 0 / 0; EUR 2 000 / 0 / 0 / 0; RUB 530 000 / 0 / 3 000 / −3 000; KZT 1 000 000 / 0 / 0 / 0;
   - таблица 2: «Итого» 2 101 750 KGS.
10. Иван: выдал 1 000 USD, взял у Ивана 300 USD, взял у Ивана 20 000 RUB. Карточка клиента: «USD: должен вам 700», «RUB: вы должны 20 000».
11. Нурлан: выдал 100 USD, затем «Мне вернули» 150 USD. На экране подтверждения есть предупреждение о переплате 50 USD. После сохранения: «Нурлан: вы должны 50 USD».
12. Помощник Айгуль:
    - сначала владелец выдаёт Тимуру в долг 1 000 USD;
    - Айгуль вносит «Мне вернули» от Тимура 1 000 USD вместо 100;
    - отменяет свою запись с причиной. Баланс Тимура и касса вернулись к прежним значениям, владелец получил уведомление;
    - вносит правильную запись на 100 USD. Тимур должен 900 USD.

    Дополнительно проверить:
    - у владельца в карточке записи Айгуль нет кнопки «Отменить запись»;
    - повторно отменить запись нельзя;
    - у записи-отмены нет кнопки отмены.

## 16. Обязательные тесты

Тесты работают с настоящим PostgreSQL. Адрес берётся из `TEST_DATABASE_URL`. Каждый тест выполняется в транзакции с откатом или на пересоздаваемой схеме.

**domain/money:**
- парсинг всех допустимых форматов и отклонение неверных (0, отрицательные, 3 знака после запятой, буквы);
- форматирование (`1 000`, `1 000,5`, `87,5`, `0,17`).

**domain/rates:**
- таблица пар из 4.5 полностью;
- пересчёт в обе стороны на примерах из 4.6;
- округление.

**services/operations:**
- `delta` для всех четырёх типов;
- баланс после серии операций, включая встречные долги и переплату;
- запрет отрицательной кассы для всех действий, уменьшающих кассу (`lend`, `repay_out` в той же и в другой валюте, отмена `repay_in` и `borrow`, корректировка в минус);
- **гонка**: две параллельные операции `lend`, каждая на 60 % остатка кассы. Успешно сохраняется ровно одна;
- идемпотентность: повторный вызов с тем же `request_id` не создаёт дубль;
- `CHECK`-ограничения: `lend` в двух валютах, пустой курс при разных валютах.

**Отмена:**
- отменить может только автор;
- отменить можно только один раз;
- нельзя отменить отмену;
- после отмены суммы `delta` по исходной записи и отмене равны нулю;
- отмена оплаты в другой валюте возвращает обе валюты в исходное состояние;
- отмена прихода при нехватке кассы отклоняется.

**Неизменяемость:** `UPDATE` и `DELETE` в `operations` и `cash_adjustments` падают с ошибкой.

**services/users:**
- нормализация никнейма;
- активация без учёта регистра;
- повторное добавление после удаления;
- удалённый пользователь не проходит проверку доступа;
- владельца удалить нельзя;
- помощник не может выполнить корректировку и управлять помощниками (`PermissionDenied`).

**services/clients:**
- дубль имени без учёта регистра;
- нельзя удалить клиента с операциями.

**Отчёты:**
- данные «Общей сводки» для состояния после сценариев 1–8 из 15.1 и курсов из сценария 9 (итог 2 101 750);
- «Кто кому должен»: клиент в обоих разделах;
- выписка: остаток на начало, остаток на конец, «Баланс после»;
- движение кассы: остаток на начало, остаток на конец;
- xlsx открывается через openpyxl и содержит ожидаемые значения в ключевых ячейках;
- PDF непустой и начинается с `%PDF`.

## 17. Что не входит в эту версию

- проценты по долгам;
- сроки возврата и напоминания;
- импорт старых данных;
- пересчёт долгов в сомы и любой общий итог долгов в одной валюте;
- редактирование и удаление операций и корректировок;
- автоматическая загрузка курсов валют;
- другие языки интерфейса;
- веб-интерфейс.

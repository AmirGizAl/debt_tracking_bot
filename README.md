# Telegram-бот учёта обменника валют

Бот заменяет ежедневную таблицу учёта обменника: обмены валют с клиентами (сразу и с отложенной
выдачей или оплатой), балансы USD, EUR, RUB, KZT и наличку в сомах, обязательства по обменам,
долги в сомах и рабочие дни. День закрывает владелец, после закрытия бот считает излишки и
присылает отчёт в Excel и PDF.

- Инструкция по работе для владельцев и помощников: [docs/user_guide.pdf](docs/user_guide.pdf).
  После изменений, которые видят пользователи, пересоберите её: `python docs/build_user_guide.py`.
- Полная спецификация: [TZ.md](TZ.md) (версия 2.0).
- Решения по местам, которые ТЗ не описывает, и согласованные отличия от ТЗ:
  [docs/decisions.md](docs/decisions.md).
- Как бот переделывался с версии 1 («учёт долгов и кассы»): [docs/V2_PLAN.md](docs/V2_PLAN.md).

Для работы нужен сервер (или компьютер) с Docker и Docker Compose v2. Всё остальное запускается
в контейнерах: бот, PostgreSQL 16 и Redis 7.

## Ветки

- `master` — версия для сервера, откуда Telegram доступен напрямую (например, VPS за пределами
  России). Именно её разворачивают на сервере.
- `ru_version` — то же самое плюс клиент прокси Hysteria2 в `docker-compose.yml`: бот ходит
  в Telegram через прокси. Для запуска внутри России.

Изменения делаются в `master` и затем переносятся в `ru_version`:

```bash
git checkout ru_version && git merge master && git checkout master
```

## 1. Создайте бота у @BotFather

1. Откройте в Телеграме [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Напишите название бота, например «Учёт обменника».
3. Напишите имя пользователя бота. Оно должно заканчиваться на `bot`, например `my_exchange_bot`.
4. BotFather пришлёт токен вида `123456789:AAH...`. Это `BOT_TOKEN`. Никому его не показывайте:
   с токеном можно управлять ботом.
5. Бот работает в личных сообщениях, а в группу только публикует уведомления (раздел 4,
   «Уведомления в группу»). Когда бот уже добавлен в свою группу (или если группа не нужна),
   запретите добавлять его в новые группы: `/setjoingroups` → выберите бота → `Disable`.

## 2. Узнайте свой Telegram ID

Это число, по которому бот узнаёт владельца. Проще всего:

- напишите боту [@userinfobot](https://t.me/userinfobot) любое сообщение, он ответит вашим `Id`;
- или откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` после того,
  как напишете своему боту, и найдите `"from":{"id": ...}`.

## 3. Заполните `.env`

```bash
cp .env.example .env
```

Откройте `.env` и укажите:

| Переменная | Что указать |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `OWNER_TELEGRAM_IDS` | Telegram ID владельцев через запятую, например `111111111,222222222` |
| `GROUP_CHAT_ID` | пусто или ID группы для уведомлений (раздел 4, «Уведомления в группу») |
| `DATABASE_URL` | оставьте как есть для запуска через Docker |
| `REDIS_URL` | оставьте как есть; если пусто, состояния диалогов живут только в памяти и теряются при перезапуске |
| `TZ` | часовой пояс для дат и времени записей, отчётов и логов: `Europe/Moscow` (московское время) |
| `LOG_LEVEL` | `INFO` (или `DEBUG` для подробных логов) |
| `PROXY_URL` | обычно пусто; нужен, только если Telegram заблокирован (раздел 8) |

Владельцы — все, чьи ID перечислены в `OWNER_TELEGRAM_IDS`, права у них одинаковые. Если убрать ID
из списка, этот владелец потеряет доступ, а его записи останутся с пометкой «(удалён)».

## 4. Запуск

```bash
docker compose up -d --build
```

При старте контейнер бота сам применяет миграции базы данных, затем запускает бота.
Проверить, что всё работает:

```bash
docker compose ps
docker compose logs -f bot
```

В логах должно появиться `Bot started … open day №1`. Откройте бота в Телеграме и нажмите
«Старт»: появится главное меню «День №1. Выберите действие:», а под полем ввода — панель с теми же
разделами. Панель видна всегда; если она пропала, отправьте `/start`.

### Первый день: начальные балансы

До первого закрытия дня внесите деньги, которые есть на начало работы: «Настройки» →
«Начальные балансы» → «Внести» → валюта → сумма → «Сохранить». По одной записи на каждую валюту,
где есть деньги (например, 10 000 USD и 1 000 000 KGS). От них бот считает излишки: пока
записей нет, излишки равны нулю при любых курсах.

Ошибку в начальном балансе можно исправить, пока открыт день №1: откройте запись («Балансы» →
«Записи дня»), нажмите «Отменить запись» и внесите сумму заново. После первого закрытия дня
начальные балансы больше не меняются: недостачу или излишек после пересчёта денег вносят
корректировкой.

### Работа с ботом

| Раздел | Что делает |
|---|---|
| Обмен | Клиент отдаёт одну валюту и получает другую. Сразу или с выдачей или оплатой позже; без имени — только мгновенный обмен. Одна валюта с обеих сторон — перевод без конвертации |
| Ждут выдачи | Кому обменник ещё должен выдать деньги по обменам. Нажмите на строку — выдача, есть кнопка «Всю сумму» |
| Ждут оплаты | Кто ещё должен обменнику по обменам. Нажмите на строку — получение |
| Долги в сомах | «Выдал в долг», «Мне вернули», «Взял в долг», «Я вернул», «Кто кому должен» |
| Клиенты | Поиск, карточка с обязательствами, «Выдать», «Получить», история записей, выписка |
| Балансы | Пять балансов открытого дня, «Записи дня», «Корректировка» (только владельцы) |
| Отчёты | Предварительный отчёт, архив закрытых дней, кто кому должен, журнал записей, движение балансов, выписка по клиенту — в Excel или PDF |
| Закрыть день | Только владельцы: курсы → проверочный экран с излишками → закрытие |
| Настройки | Только владельцы: помощники и начальные балансы |

Деньги не уходят в минус: если денег не хватает, бот скажет об этом до сохранения и запись не
сохранит. Ошибочную запись отменяет её автор: карточка записи → «Отменить запись» → причина.
Отмена попадает в текущий день; если отменил помощник, владельцы получают уведомление.
Корректировку отменить нельзя, ошибку исправляют встречной корректировкой.

**Закрытие дня.** Владелец нажимает «Закрыть день», вводит курсы «Сколько сомов за 1 USD?» для
валют, где есть деньги или обязательства (кнопка «Как в прошлый раз» подставит курс прошлого
закрытия), проверяет цифры и нажимает «Закрыть день №N». Бот сохраняет отчёт дня, присылает всем
владельцам Excel и PDF и открывает следующий день. Отчёт закрытого дня не меняется: его можно
скачать повторно из «Отчёты» → «Архив закрытых дней». Посмотреть цифры без закрытия можно
в «Отчёты» → «Предварительный отчёт».

Помощники добавляются в «Настройки» → «Помощники» → «Добавить» по никнейму в Телеграме.
Помощник должен открыть бота и нажать «Старт»; у него обязательно должен быть никнейм. Помощник
делает обмены, выдачи, получения и долги в сомах, видит балансы и отчёты, но не закрывает день,
не вносит корректировки и начальные балансы.

### Уведомления в группу

Бот может публиковать в группу Telegram новые записи владельцев и помощников (с балансами и
обязательствами после записи), отмены записей с причиной, корректировки, подключение и удаление
помощников и итог закрытия дня (файлы отчёта получают только владельцы). В группе бот ничего не
отвечает; работа с ботом по-прежнему идёт в личных сообщениях.

1. Создайте группу (или возьмите готовую) и добавьте в неё бота: «Добавить участника» → найдите
   бота по имени пользователя. Добавлять должен владелец, а бот в этот момент должен работать.
2. Бот пришлёт владельцу в личные сообщения строку вида `GROUP_CHAT_ID=-1001234567890`.
   Вставьте её в `.env` и перезапустите бота: `docker compose up -d --build`. Если сообщение
   не пришло (например, бот был в группе раньше), удалите бота из группы и добавьте снова.
3. В логах бота при старте появится `New records are posted to the group '…'`. Если вместо
   этого `Cannot reach the group`, бота нет в группе или в `GROUP_CHAT_ID` другой ID.

Если в группе писать могут только администраторы, сделайте бота администратором. Если Telegram
превратит группу в супергруппу (так бывает при смене настроек группы), у неё сменится ID: бот
продолжит публиковать уведомления, а в логах напишет новый ID для `.env`.

## 5. Обновление

Получите новую версию кода (например, `git pull`) и пересоберите контейнер:

```bash
docker compose up -d --build
```

Миграции базы применяются автоматически при старте. Данные сохраняются.

### Переход с версии 1 («учёт долгов и кассы»)

1. В `.env` замените строку `OWNER_TELEGRAM_ID=…` на `OWNER_TELEGRAM_IDS=…` (через запятую можно
   перечислить нескольких владельцев). Со старой переменной бот версии 2 не запустится.
2. Сделайте резервную копию базы (раздел 7).
3. Обновите бота. При первом запуске миграция удалит записи и корректировки кассы версии 1:
   у версии 2 другой учёт, и старые записи в него не переносятся. Пользователи, помощники и
   клиенты сохраняются.
4. Внесите начальные балансы (раздел 4, «Первый день»).

Старые версии Docker Compose (например, 2.3) собирают новый образ, но оставляют работать старый
контейнер. Если после обновления в `docker compose logs bot` нет нового `Bot started`,
пересоздайте контейнер бота:

```bash
docker compose up -d --no-deps --force-recreate bot
```

## 6. Остановка

```bash
docker compose stop        # остановить, всё сохраняется
docker compose start       # запустить снова
docker compose down        # удалить контейнеры; данные в томах сохраняются
```

**Не используйте `docker compose down -v`**: флаг `-v` удаляет тома, то есть всю базу данных.

## 7. Резервная копия базы

Все записи, клиенты, рабочие дни и их отчёты хранятся в PostgreSQL. Redis хранит только
незавершённые диалоги, его копировать не нужно.

Сделать копию (файл появится в текущей папке):

```bash
docker compose exec -T db pg_dump -U debtbot -d debtbot -Fc > backup_$(date +%F).dump
```

Копию стоит делать регулярно и хранить на другом компьютере или в облаке. Пример ежедневной
копии в 03:00 через `crontab -e` (замените путь на папку проекта):

```cron
0 3 * * * cd /opt/debt_tracking_bot && docker compose exec -T db pg_dump -U debtbot -d debtbot -Fc > backups/backup_$(date +\%F).dump
```

Восстановить из копии (все текущие данные заменятся данными из файла):

```bash
docker compose stop bot
docker compose exec -T db pg_restore -U debtbot -d debtbot --clean --if-exists < backup_2026-09-27.dump
docker compose start bot
```

## 8. Если Telegram недоступен

Если в логах бота повторяется `Telegram is unreachable` или `Request timeout error`, провайдер
блокирует `api.telegram.org`. Проверка с сервера:

```bash
curl -m 8 -o /dev/null -w "HTTP %{http_code}\n" https://api.telegram.org
```

Тогда укажите в `.env` прокси, через который Telegram доступен (HTTP или SOCKS5):

```
PROXY_URL=socks5://user:password@proxy-host:1080
```

и перезапустите: `docker compose up -d --build`.

Если прокси — сервер Hysteria2, используйте ветку `ru_version`: в ней клиент Hysteria2 уже
подключён в `docker-compose.yml`, настройка описана в её README.

## 9. Для разработчика

Python 3.12. Установка и проверки:

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
ruff check . && ruff format --check .
```

Тесты работают с настоящим PostgreSQL. Отдельная одноразовая база для тестов (её данные живут
в памяти контейнера):

```bash
docker compose -f docker-compose.test.yml up -d
export TEST_DATABASE_URL=postgresql+asyncpg://debtbot:debtbot@localhost:55432/debtbot_test
pytest
```

Тесты пересоздают схему через миграции Alembic и запускаются только на базе, в имени которой
есть `test`. Кроме домена и сервисов, тесты проходят через настоящий диспетчер aiogram с
поддельным Telegram (`tests/bot/harness.py`): он проверяет HTML, длину callback-данных и
сообщений так же строго, как Telegram.

Новая миграция: `alembic revision --autogenerate -m "..."`. Проверьте файл вручную: триггеры,
CHECK-ограничения и условия частичных индексов autogenerate не видит. Тест
`tests/test_schema.py::test_models_match_migration` следит, чтобы модели совпадали со схемой.

Зависимости для Docker закреплены в `requirements.lock`. После изменения `pyproject.toml`:

```bash
uv pip compile pyproject.toml --universal --python-version 3.12 --no-header -o requirements.lock
```

### Структура

```
app/
  __main__.py        точка входа: python -m app (синхронизация владельцев, день №1)
  config.py          настройки из .env
  domain/            чистые правила: валюты, суммы, курсы, проводки, предупреждения,
                     отчёт дня и излишки, даты, ошибки
  services/          работа с базой: журнал и проводки (ledger), обмены, выдачи, долги,
                     корректировки, начальные балансы, отмены, рабочие дни, отчёты
  bot/               Telegram: тексты, клавиатуры, сценарии, обработчики, middleware
  db/                модели SQLAlchemy
migrations/          Alembic
tests/               тесты (pytest), в том числе приёмочные сценарии ТЗ 17.1
```

Учёт построен на проводках: каждая запись — строка в `operations` и проводки в
`operation_entries`; балансы и обязательства — суммы проводок. Обе таблицы неизменяемы
(триггеры запрещают `UPDATE` и `DELETE`), ошибки исправляются отменой или корректировкой.

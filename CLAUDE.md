# Telegram-бот учёта обменника валют

Полная спецификация находится в `TZ.md` (версия 2.0). Прочитай её перед любой задачей в этом репозитории.
В репозитории лежит бот версии 1 («учёт долгов и кассы»). Его нужно переделать по разделам 16 и 17 `TZ.md`. План перехода и состояние этапов — в `docs/V2_PLAN.md`.
Файл `docs/client_description.pdf` описывает версию 1 и устарел.
Решения по местам, которые ТЗ не описывает, и согласованные с заказчиком отличия от ТЗ (например, московское время вместо `Asia/Bishkek`) собраны в `docs/decisions.md`. Согласованное там важнее `TZ.md`.

## Команды

- Установка для разработки: `pip install -e ".[dev]"`
- Линтер и форматтер: `ruff check . && ruff format --check .`
- Тесты: `pytest`. Нужен PostgreSQL, адрес задаётся в `TEST_DATABASE_URL`.
  Тестовая база: `docker compose -f docker-compose.test.yml up -d`,
  `TEST_DATABASE_URL=postgresql+asyncpg://debtbot:debtbot@localhost:55432/debtbot_test`.
- Новая миграция: `alembic revision --autogenerate -m "..."`. Обязательно проверь сгенерированный файл вручную: триггеры, `CHECK` и частичные индексы autogenerate не видит.
- Применить миграции: `alembic upgrade head`
- Запуск: `docker compose up -d --build`

## Правила

- Работай по этапам из `TZ.md` (раздел 17), по одному этапу за раз. После этапа тесты должны быть зелёными, `ruff` чистым, затем делается коммит.
- Бизнес-правила из `TZ.md` не меняй. Если что-то неясно или противоречиво, спроси, не додумывай.
- Деньги и курсы храни только в `Decimal`, `float` не используй. Округление `ROUND_HALF_UP` до 0,01.
- Учёт построен на проводках: каждая запись — строка в `operations` и проводки в `operation_entries`. Балансы, обязательства и начальная точка вычисляются суммированием проводок, отдельными полями они не хранятся.
- Таблицы `operations` и `operation_entries` неизменяемы: в коде никаких `UPDATE` и `DELETE` для них. Ошибки исправляются отменой (сторно) или встречной корректировкой.
- Любое уменьшение баланса выполняется в транзакции с `pg_advisory_xact_lock` по валюте и проверкой, что баланс не уйдёт в минус.
- Каждая запись создаётся под `SELECT … FOR SHARE` на открытый день и получает его `day_id`. Закрытие дня берёт `FOR UPDATE`. Закрытый день не меняется.
- Расчёт отчёта дня и излишков — чистая функция в `app/domain/day_report.py`. Начальные балансы пересчитываются по курсам того же отчёта.
- Бизнес-логика живёт в `app/domain` (чистые функции) и `app/services` (транзакции и проверки прав). Хендлеры aiogram остаются тонкими.
- Права проверяются и в интерфейсе (лишние кнопки скрыты), и в сервисах (`PermissionDenied`). Владельцы берутся из `OWNER_TELEGRAM_IDS`.
- Все тексты для пользователя хранятся в `app/bot/texts.py`. Пользовательские данные в HTML-сообщениях экранируются.
- Перед удалением таблиц версии 1 проверь, есть ли в них данные. Если есть, остановись и спроси.
- Для тестов используй настоящий PostgreSQL, SQLite не подходит.

## Ветки

- `master` — основная ветка, она разворачивается на сервере. Вся разработка ведётся здесь.
- `ru_version` — `master` плюс клиент Hysteria2 (прокси до Telegram) для запуска внутри России.
  От `master` отличается только файлами прокси: `docker-compose.yml`, `.env.example`,
  `hysteria/config.example.yaml`, раздел о прокси в `README.md`.
- После коммитов в `master` перенеси их в `ru_version` слиянием:
  `git checkout ru_version && git merge master && git checkout master`.
  Не используй cherry-pick и rebase для `ru_version`.
- Правки, касающиеся только прокси, делаются прямо в `ru_version` и в `master` не попадают.
- На GitHub (`origin`) хранятся обе ветки.

# Решения по местам, которые ТЗ не описывает

Бизнес-правила ТЗ не менялись. Ниже перечислено, как реализованы места, где ТЗ молчит или
допускает два прочтения. Каждый пункт легко поменять, если нужно иначе.

## Согласовано с заказчиком (27.09.2026)

1. **Формат сумм.** Нулевые копейки скрываются, ненулевые показываются двумя знаками:
   `1 000`, `1 000,50`. Пример `1 000,5` из раздела 16 относится к формату курса: курсы выводятся
   без хвостовых нулей (`87,5`, `0,17`, `1 000,5`).
2. **Смена владельца.** Если в `OWNER_TELEGRAM_ID` указать другой аккаунт, прежний владелец
   помечается удалённым: доступ пропадает, записи остаются с пометкой «(удалён)». При возврате
   прежнего ID восстанавливается та же запись пользователя.
3. **«Недавние» клиенты.** Порядок по последней активности: время последней записи, а для
   клиента без записей — время создания.

## Интерфейс

4. **Переходы после сохранения.** Правило «итог новым сообщением, затем главное меню» применяется
   ко всем сохранениям: записи, отмене, корректировке, добавлению и изменению клиента,
   добавлению и удалению помощника. К итогу добавлены кнопки «Открыть запись» и «Открыть
   клиента».
5. **Кнопки «Назад».** Есть на всех шагах, включая экраны подтверждения («Сохранить /
   Не сохранять / Назад», «Да, отменить / Назад / В меню»). Карточка клиента дополнительно
   имеет кнопку «‹ Все клиенты».
6. **Устаревшие кнопки.** Кнопки шага сценария работают только на сообщении, которое
   показывает текущий шаг. Кнопки старых сообщений отвечают «Это действие устарело». Кнопки
   просмотра (карточки, списки, «Открыть запись» в уведомлении) работают всегда.
7. **Уход из сценария.** Любая навигация в другой раздел, `/menu`, `/start`, `/cancel` и
   «В меню» прерывают текущий сценарий. Команды обрабатываются раньше шагов, которые ждут
   текст. Текст вне сценария показывает главное меню.
8. **Ранние проверки кассы.** Кроме шага суммы (ТЗ 7.4), касса проверяется при нажатии
   «Отменить запись», если отмена забирает деньги из кассы, чтобы не вводить причину зря.
   Окончательная проверка всегда выполняется при сохранении под блокировкой.
9. **Нехватка денег при сохранении.** Сценарий завершается сообщением из ТЗ 7.4 с последней
   строкой «Запись не сохранена.» (так же для отмены и корректировки).
10. **Комментарий клиента** можно удалить кнопкой «Удалить комментарий» при изменении.
11. **Сортировка списков в боте** («История записей», «Движение денег»): по учётной дате,
    затем по времени внесения, от новых к старым.
12. **Выбор клиента для выписки** работает как в ТЗ 12.2, но без кнопки «Новый клиент».

## Учёт

13. **Верхняя граница пересчёта.** Сумма списания с долга после пересчёта по курсу тоже должна
    быть не больше `999 999 999 999,99`, иначе бот просит проверить сумму или курс (как при нуле
    в ТЗ 4.6). Это ограничение формата `NUMERIC(18,2)`.
14. **Точность пересчёта.** Пересчёт выполняется с точностью 60 знаков и одним округлением
    `ROUND_HALF_UP` до копеек, чтобы на больших суммах не было двойного округления.
15. **Дополнительные CHECK в базе.** Кроме ограничений из ТЗ 6.3: курс больше 0, знаки
    `debt_delta` и `cash_delta` соответствуют типу записи (ТЗ 7.1) и отмене.
16. **Никнейм помощника** после активации не обновляется: по ТЗ при /start обновляется только имя.
17. **Повторное добавление удалённого помощника** восстанавливает ту же запись пользователя
    (ТЗ 9.2). Дата добавления в карточке остаётся первой.

## Отчёты

18. **Периоды.** «Этот месяц» и «Прошлый месяц» — календарные месяцы целиком, «С начала года» —
    с 1 января по сегодня, «Всё время» — без границ. Для «Указать даты» будущие даты разрешены.
19. **Имена файлов** для «Всё время»: `Все_записи_всё_время.xlsx`. В имени выписки из имени
    клиента убираются символы, недопустимые в именах файлов.
20. **Excel.** Отчёты с несколькими таблицами разбиты на листы (сводка — два листа, «Кто кому
    должен» — «Вам должны» и «Вы должны», движение кассы и выписка — по листу на валюту), чтобы
    у каждой таблицы была закреплённая шапка и автофильтр. В «Все записи» валюта вынесена в
    отдельные колонки «Валюта долга» и «Валюта оплаты», чтобы суммы оставались числами.
21. **Выписка по клиенту** показывает валюты, в которых у клиента есть записи с датой не позже
    конца периода.
22. **Движение кассы.** Запись-отмена описывается как «Отмена записи №N — Клиент».

## Инфраструктура (вне бизнес-правил)

23. **Прокси до Telegram** (`PROXY_URL`): на сервере разработки Telegram доступен только через
    прокси. Клиент Hysteria2 подключён в отдельной ветке `ru_version` (раздел «Ветки» в README).
24. Бот отвечает только в личных сообщениях; группы и каналы игнорируются. Альбом из нескольких
    фото получает один ответ, а не по ответу на каждое фото.
25. Отдельная тестовая база: `docker-compose.test.yml`.
